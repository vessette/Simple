Workflow 2

How a capability earns autonomy

Each capability climbs on its own, never the agent as a whole. Every arrow is a gate: the accountable sales manager approves the next rung, on evidence, and only that rung. Every capability is at R0 today. R3 is folded into R4 here, and R7 to R9 are beyond what any sales capability is allowed.

What never counts as evidence

  • A story being marked complete
  • Time passing without incident
  • A good conversation or a demo
  • A test that passes only against mocks

What the platform enforces anyway

  • No tools granted: anything above R2 is forced back to R2
  • Production needs a separately approved pilot, never approval alone
  • One capability's level never raises another's
  • Sending messages is denied to every agent by default

When it steps back down

  • A result disagrees with the manager's own decision beyond the agreed rate
  • A figure is reported that can't be traced to its source
  • Anyone is contacted, charged or refunded without a person
  • The manager asks, for any reason

Workflow 3

How each piece of work gets built

The same seven steps for every story, from the course plan to a verified change. Purple steps are done by a person; the rest are done with Claude Code and checked by tests.

    Running in the background

    Every changeSession logEach change is recorded with its date, what changed and the evidence, in the same pull request.
    Every finished taskLiving pagesThe roadmap, capability map and weekly one-pager are republished so they match the work.
    Weekdays, 8 AM CentralScheduled refreshA cloud job recounts progress and updates the one-pager's figures, committing only when something changed.
    On every pushPublish to PagesA GitHub Actions workflow publishes the one-pager, and nothing else, to GitHub Pages.

    Built from the capability specifications and project process in github.com/vessette/Simple. People are referred to by role. Ceilings and rungs are drafts until the accountable manager reviews them.
